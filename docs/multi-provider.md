# Multi-provider backend evidence

This records the completed backend stage from 03aa914 to b3ca864. It preserves GDP/authentication and implements one source path at a time. The subsequent [frontend stage](frontend.md) consumes these stored-data contracts; no new feed is promoted by UI integration. Application inputs are live official responses; fixtures are compressed original responses used only by offline tests. Diagnostic caches and private proof databases stay ignored.

## GST — implemented, including five completed FYs

- Discovery: [statistics page](https://www.gst.gov.in/download/gststatistics) links the gross/net workbook. The page's public news client calls [GSTN news JSON](https://www.gst.gov.in/fomessage/newsupdates); title, month and exact PDF link select the latest monthly release. No permanent September URL is baked into the collector.
- Actual sources: [monthly workbook](https://tutorial.gst.gov.in/offlineutilities/gst_statistics/Gross_Net_Tax_collection.xlsx) and [September release](https://tutorial.gst.gov.in/downloads/news/final_gst_revenue_report_for_publishing_monthly_sep_2026.pdf). Five-page PDF reviewed; first-page A.3 gross band is separate from B refunds and C net. Monthly values and FYTD columns are not interchangeable.
- Definition: original totals include compensation cess in older sheets and exclude it in newer sheets. Primary comparable gross excludes cess, with original totals/methodologies and published cess kept separately. Gross components reconcile within publication rounding (workbook 0.02 crore, integer PDF 2 crore). Do not compare inclusive/exclusive reported totals across a methodology break.
- Workbook anomalies: Jan-25 uses B=current/C=prior with “Daily” heading; Nov-25 spells “Montly”. Accept these only for those exact sheet periods and valid adjacent-year month headers. Cached numeric XML values are read as Decimal text; formulas/macros are never executed.
- Storage/API: 120 raw/normalised observations; protected `/api/v1/panels/gst` ready/200. [Live proof](evidence/2026-10-15/gst-live.json). Derived annual totals/averages require 12 published months. FYTD averages divide by actual published-month count and identify their input months; missing months are not zeroes. Derived values carry canonical input references.
- Historical coverage was subsequently completed through the [nine-year GSTN report](https://tutorial.gst.gov.in/offlineutilities/gst_statistics/9YearsReport.pdf), discovered from the statistics page (the collector does not hard-code the number nine). Payment/Monthly Collections tables explicitly include domestic supplies and imports, CGST/SGST/IGST/cess, and completed April–March windows. Monthly components reconcile within 2 crore; the sum of 12 integer-rounded months reconciles to the published annual amount within 6 crore. No audited/final status or publication date is invented for this report.
- Current verified coverage: April 2020–September 2026, 78 months, 228 raw/normalised observations and five non-null completed-FY totals/averages. [Extended live proof](evidence/2026-10-15/gst-history-live.json) supersedes the initial 42-month proof. Annual averages use the canonical monthly sums, which can differ slightly from independently rounded/restated source annual/YTD totals.
- The 24 Council PDFs for FY 2021–22/2022–23 were reachable, but January 2022 has no extractable text and early releases include figures subsequently revised. They were not promoted as collectors or committed as redundant fixtures. The linked GSTN year report supplies revised history instead (e.g. January 2022 reported gross 140,986; comparable ex-cess 131,290).
- Reproduce: `scripts/verify_sources.py --groups gst` via the project Python environment. Offline tests verify original hashes/reviewed values, Jan-25 assignment, methodology separation, missing-month averages, idempotency, failure retention and restart/API reads.

## Dependencies

Beautiful Soup handles legacy official HTML tables; pypdf handles official machine-readable release PDFs. Existing HTTPX, sqlite3, Pydantic and Decimal remain the transport/storage/validation/arithmetic tools. No ORM, task queue, scheduler framework, spreadsheet writer or browser scraper is added. Locks pin exact versions.

`truststore` is justified specifically by the Gazette: HTTPX's default CA bundle failed issuer-chain validation; a native system-store SSL context succeeded with certificate and hostname verification enabled. Use an explicit context for that collector, never global SSL injection or `verify=False`. Production Linux certificate-chain access still needs verification on its actual host; install normal OS CA certificates and resolve issuer-chain failures without weakening TLS. See the [library's native-context documentation](https://truststore.readthedocs.io/en/latest/).

## Merchandise trade — implemented

- Discovery: [Commerce release listing](https://www.commerce.gov.in/ministryofcommerce/taxonomy/term/530), normal pagination, monthly release node metadata and PDF attachments. The latest monthly document is parsed; April publication nodes are examined for the latest completed March FY. Every document's reporting headers and release date are validated. Page/node/PDF budgets bound discovery.
- Actual current sources: [August 2026 release](https://www.commerce.gov.in/files/d-m-y/PIB%20Release%20-%20August%202026.pdf) and [March 2026 release](https://www.commerce.gov.in/files/d-m-y/PIBRelease.pdf). The August document says September 15; its listing says September 16. Store the document's publication date, not the listing date.
- Historical sources: original Commerce WordPress March PDF URLs returned HTTP 404 at runtime despite search-engine copies. Accepted official Ministry releases on PIB remain accessible: [March 2024](https://www.pib.gov.in/PressReleasePage.aspx?PRID=2017942&reg=48&lang=2), [March 2023](https://www.pib.gov.in/PressReleasePage.aspx?PRID=1916220&reg=48&lang=2). These are explicit bootstrap references, configurable with `TRADE_HISTORY_URLS` (pipe-separated HTTPS PIB URLs), not a fixed collection-year ceiling. Future/current discovery remains dynamic.
- Validation: only the Merchandise block of Tables 1/2, USD billion, exact matching current/prior month/FYTD/FY headers. No service estimates, combined-trade balances or INR amounts. Per-point status is unspecified where merchandise finality is not explicit. Later publication dates win overlapping historical periods (FY 2022–23 exports 451.07 in the 2024 vintage replaces 447.46 in the 2023 vintage).
- Canonical balances subtract published exports/imports with input references. Their rounding can differ from source headlines: 437.06 − 677.24 = −240.18, while the 2024 release's separately rounded deficit headline is 240.17. Preserve arithmetic consistency; do not copy the headline into the canonical balance.
- Coverage/API: five completed FYs 2021–22 through 2025–26, current/prior August monthly and April–August FYTD, plus March monthly comparators. 33 stored raw/derived points; protected `/api/v1/panels/trade` ready/200. [Live proof](evidence/2026-10-15/trade-live.json). Earlier windows beyond these verified bootstrap releases remain incomplete if configured. Reproduce with `scripts/verify_sources.py --groups trade`.
- Transport extension: normal public listing POSTs can use the same retry/cooldown path. An outer monotonic request timeout also bounds slow streams; HTTPX's per-chunk read timeout alone does not bound a dripping response. No redirect or TLS-verification bypass was added.

## CPI — implemented, bases kept separate

- Diagnosis/discovery: direct `cpi.mospi.gov.in` timed out; a newer product page returned only an HTML shell; GET against the newer API returned 403. Inspecting the site's public client showed that its release list uses POST. The normal unauthenticated POST to `https://www.mospi.gov.in/api/latest-release/get-web-latest-release-list` succeeded with `search_term=CPI`, 100/page, descending publication date. Pagination/title/attachment validation discovers actual releases, not workshop notices. No client secret or special access header was used.
- Actual publications: the discovered September 2026 release (October 12) and December 2025 release (January 12, 2026). Compressed original PDF/listing fixtures include SHA-256 and reviewed values; relevant table pages were rendered/visually checked.
- Definition: All-India **combined general/headline** YoY inflation in percent, not rural, urban or food CPI. New-base Annexure IV publishes combined September 5.54 and August 4.83; badge difference is 0.71 pp. Rates use unrounded source indices, so published rates are accepted instead of recomputing from rounded index levels.
- Methodology: last 2012=100 release explicitly ends at December 2025. Keep `cpi_yoy_2012` and `cpi_yoy_2024` separate. The latter begins January 2026. Its 2025 index levels do not establish 2025 YoY rates; no such rates are invented, and January 2026 has no cross-base comparison. Unknown future bases fail closed pending review.
- Status/coverage: the accepted old-base release supplies 2020–2025 within the configured rolling collection window; April/May 2020 were not compiled and remain null gaps. New-base January–September 2026 rates are stored separately. September is provisional, August explicitly final; older historical status stays unspecified except explicitly labelled November/December 2025. Collection time remains distinct from each release date and reporting month.
- Proof: 79 non-null CPI observations, 81 reporting months including the two null gaps; protected `/api/v1/panels/inflation` ready/200. [Live proof](evidence/2026-10-15/inflation-live.json). Repeat ingestion, base isolation, unknown-base rejection, source failure independence, persistence and stored-only reads are tested.

## Inflation-target policy — implemented independently

- Actual source: [Gazette notification S.O. 1580(E)](https://egazette.gov.in/WriteReadData/2026/271285.pdf), Ministry of Finance/DEA, March 25, 2026. The English notification is parsed and authority, section 45ZA, publication date, three percentages and validity dates are validated.
- Target 4%, lower 2%, upper 6%; validity **April 1, 2026–March 31, 2031**. Three canonical policy points have a `policy_validity` period, not synthetic monthly observations. Inflation panel `policies[]` references these points and reports whether a verified window is active at request time.
- Discovery is an explicit reviewed notification reference, configurable via `INFLATION_POLICY_URL`; this is not an automatic search of all new Gazette notices. The collector revalidates it weekly independently of CPI. After expiry the API applies no policy automatically; a successor notification must be reviewed/configured.
- TLS failure was runtime trust-chain resolution, not provider rejection. Native system trust resolved it without bypassing validation. [Live proof](evidence/2026-10-15/inflation-live.json) includes collection, private SQLite and protected API read for this separate group. Policy timeout leaves CPI observations and prior policy provenance intact; expiry tests mark the policy inactive.
